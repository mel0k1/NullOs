# NullOs — Аудит и исправления (Layer 3, сентябрь 2026)

Полный аудит ядра NullOs (≈39 тыс. строк C/ASM): 4 параллельных исследования
(память, планировщик/процессы, сеть/драйверы, VFS/ФС) + личная верификация
каждой находки. Исправлено ~30 багов в 15 файлах ядра и `include/mm.h`.
Ядро пересобрано (`make all`, gcc/ld — успешно, новых предупреждений нет).

Каждый фикс помечен в коде комментарием `FIX(#тег)` с описанием корня и
сценария отказа. Ниже — сводка по убыванию критичности.

---

## Критические (эксплуатируемые примитивы порчи памяти ядра / DoS)

### 1. `#pmm-free-never` — kernel/mm.c `pmm_free_page()`
Guard зоны carve не имел верхней границы: `page_num >= carve_start_page`
блокировал освобождение **всех** фреймов ≥ 128 МБ (зона — всего 2 МБ).
`pmm_free_page` — единственный runtime-путь освобождения PMM, значит
каждый фрейм выше 130 МБ был одноразовым: exit/munmap/COW-освобождения
молча ничего не делали, PMM необратимо истощался под обычной нагрузкой
fork/exec/exit. Фикс: guard ограничен фактическим концом зоны
(`carve_end`).

### 2. `#uaccess-supervisor-hole` — kernel/mm.c + kernel/syscall.c
`user_range_ok()` отсекал только окно ядра [1 ГБ, 2 ГБ), но каждый
пользовательский PML4 — клон ядра и несёт ещё ДВА супервайзорных окна:
identity [4 МБ, 1 ГБ) (в нём куча ядра на PA 16–80 МБ!) и MMIO
[2 ГБ, 4 ГБ). Процесс ring 3 мог передать `buf = 0x2000000` в
`read/write/wait4/...` — ядро в супервайзорном режиме читало/писало свою
собственную кучу по указанию атакующего (утечка/порча, ни один fault не
взлетал — страницы present). Фикс: новая `vmm_range_is_user()` обходит
таблицы активного PML4 и требует VMM_USER на каждой present-странице
диапазона; not-present страницы проходят (их обслуживает demand pager —
сохранена семантика ОС).

### 3. `#icmp-total-len-smash` — kernel/net.c
`total_len` из IP-заголовка принятого пакета никогда не сверялся с
фактической длиной кадра. Один кадр с `total_len=0xFFFF` заставлял
`icmp_echo_reply` копировать ~64 КБ через 1480-байтный буфер на стеке
ядра (сборка без stack-protector) — удалённо триггерируемый смэш стека
ring 0. Фикс: clamp `total_len` к длине кадра, `ihl >= 20`, sanity
`total_len >= sizeof(ip_hdr_t)`.

### 4. `#udp-send-overflow` — kernel/net.c + syscall.c
Капы UDP-payload стояли на 1500 (sys_write) / NET_MTU (sendto), а в
кадровом буфере места ровно 1472 байта payload: 28 контролируемых
атакующим байт ложились за границу 1514-байтного стекового буфера ядра,
порча соседних локальных указателей → вторичные дикие записи. Фикс:
кап 1472 в обоих syscall-путях + защитный клэмп внутри `net_udp_send`.

### 5. `#ioctl-arg-hole` — kernel/evdev.c + kernel/drm.c
`evdev_ioctl`/`drm_ioctl` использовали `arg` из ring 3 без валидации:
EVIOCGVERSION писал 4 байта по любому адресу, EVIOCGBIT делал `kmemset`
до 256 байт, DRM_IOCTL_VERSION писал девять u64 по произвольному адресу,
GETRESOURCES/GETCONNECTOR гнались за указателями, прочитанными из
невалидируемой структуры (двойное разыменование). Полноценный примитив
записи в память ядра, доступный из ring 3. Фикс: каждая ветка
валидирует окно через новый экспорт `syscall_user_range_ok()`
(включая подссылки name_ptr/crtc_ptr/modes_ptr/...).

### 6. `#fd-oob-epollwait` / `#fd-oob-tfd` / `#fd-oob-ftruncate` — syscall.c
`epoll_wait`, `timerfd_settime/gettime`, `ftruncate` индексировали
`proc_fds[fd]` (16 слотов) по сырому u64 из ring 3 без bounds-проверки:
`epoll_wait(0x1000000000, ...)` = OOB-чтение с#GP/halt машины; в ftruncate
мусорный mfd-encoding позволял `pmm_free_page()` со «скими» физическими
адресами. Фикс: проверки `fd < PROC_FD_MAX && used` + корректный encoding
в каждой функции.

### 7. `#execve-raw-ptr` — kernel/proc.c
Путь и массив argv в `proc_do_execve` разыменовывались вообще без
валидации: `execve((char*)0xFFFF800000000000, ...)` = kernel-fault →
halt всей машины; элементы argv без исключения kernel-window позволяли
собрать argv из памяти ядра (раскрытие в serial-лог и в образ ребёнка).
Фикс: `copy_user_path` и `user_str_ok` валидируют постранично, массив
argv — через `syscall_user_range_ok`.

### 8. `#getcwd-raw-ptr` — syscall.c
Единственный путь с записью по непроверенному указателю: 2 байта `"/"`
по любому адресу из ring 3 (kernel-half указатель = halt). Фикс:
`user_range_ok(a1, 2)`.

### 9. `#elf-offset-wrap` — kernel/elf.c + proc.c
`e_phoff + phnum*phentsize > size` и `p_offset + p_filesz > size`
переполняются (u64 wrap) на скрафченном ELF: проверки проходили, а
`data + e_phoff`/`size - src_off` давали дикий указатель/underflow ~2^63
→ OOB-чтение ядра или #PF-halt. Фикс: беззнаковые проверки без переноса
(`a > size || b > size - a`), плюс `e_phentsize >= sizeof(phdr)`.

### 10. `#ext4-path-overflow` — kernel/ext4glue.c
`ext4_attach_tree` строил пути безграничным `kstrcpy/kstrcat` в
160-байтные буферы в РЕКУРСИВНОЙ функции ring 0: скрафченный ext4-диск
с вложенностью/длинными именами перезаписывал сохранённый RBP/адрес
возврата. Фикс: ограниченные `ext4_path_join/append`, пропуск
сверхдлинных поддеревьев, лимит глубины 8.

## Высокие

### 11. `#getphys-nx` — mm.c `vmm_get_phys()`
Не маскировался бит NX (63) в leaf-PTE: все не-исполняемые страницы
давали `PA | 1<<63`, и `munmap`/`MAP_FIXED` вызывали
`pmm_free_page(PA|NX)` → page_num ≈ 2^51 вне битмапы → **тихая утечка
фрейма при каждом munmap/data-MAP_FIXED**. Фикс: маска `~(0xFFF|VMM_NX)`.

### 12. `#conread-no-yield` — syscall.c (консольный read)
Голый `sti/hlt/cli` (остаток [BISECT-D]) вместо `task_yield()`:
задача ring 3, заблокированная на stdin, морила голодом все остальные
(преемпция по умолчанию выключена), а ^Z вообще не срабатывал —
`tty_on_ctrl_z` глотает символ, а цикл никогда не перепроверял stop_sig.
Фикс: cooperative yield (как в pipe-read) + выход с частичными данными
или -EINTR при остановке задачи.

### 13. `#dup-net-catchall` + `#dup2-ref-before-fail` — syscall.c
`val <= FD_NET_BASE` гнал ВСЕ отрицательные коды ≤ -10 (unix-сокеты,
eventfd/timerfd/memfd/signalfd, epoll, evdev, DRM) в `net_socket_dup` с
фиктивным индексом → EBADF для dup любого современного fd. Хуже: dup2
декрементировал refcount цели ДО возможной ошибки — слот оставался
«открытым» с уже пониженным счётчиком, следующий close() ронял его до
нуля → преждевременный teardown pipe (читатель получал ложный EOF).
Фикс: единые `fdref_bump_enc`/`fdref_dec_enc` (знают все классы),
приобретение новой ссылки ДО освобождения цели.

### 14. `#rx-ring-guard-udp` — net.c
Guard полноты UDP RX-кольца сравнивал `(head+1)%DEPTH` с сырым
монотонным tail: после 16 прочитанных дейтаграмм сравнение не могло
сработать никогда — непрочитанные записи молча перезаписывались (тот же
класс, что уже чинили в tcp_enqueue/icmp, но пропустили здесь). Фикс:
fill-level форма `head - tail >= DEPTH`.

### 15. `#rx-error-jam` — rtl8139.c
Кадры с ROK=0 (CRC/runt/FIFO-overflow — RCR с AAP их принимает)
возвращали 0, НЕ двигая CAPR: плохой кадр навсегда оставался в голове
кольца, приём умирал до перезагрузки. Фикс: кадр потребляется и
выбрасывается; мусорная длина заголовка → ресинхронизация CAPR по
авторитетному CBA. Неполные (DMA в полёте) кадры по-прежнему ждут
(исходная семантика retry сохранена).

### 16. `#lfb-pages-per-scanline` — drm.c
Блит `d->pages[y]` верен только при pitch == 4096; буфер 640x480
(pitch 2560) читал нулевые элементы → PHYS_TO_VIRT(0) = NULL-deref в
цикле копирования. Фикс: линейное смещение → (страница, офсет) с
пересечением границ страниц.

### 17. `#fat-eoc-link` + `#fat-size-truncate` — fat32.c
После заполнения последнего кластера `current_cluster` становился
EOC-сентинелом (0x0FFFFFF8+), и продление цепочки писало FAT по индексу
`EOC*4`, усечённому до u32 (~4.3 ГБ в диск): на больших томах — порча
произвольного сектора, на маленьких — потерянная ссылка (кластер
выделен, но недостижим). Плюс размер файла перезаписывался offset'ом
безусловно — короткая перезапись длинного файла обрезала dir entry и
теряла хвостовые кластеры. Фикс: связывание с последнего ВАЛИДНОГО
кластера; размер только растёт.

### 18. `#rename-cycle` — fs.c
`fs_rename` без проверок цикла: `rename("/a", "/a/b/x")` делал /a
родителем /a/b и наоборот → `fs_get_path()` зацикливался навечно (hang
на следующем pwd/sync). `rename("/a/b","/a")` освобождал собственного
родителя источника. Фикс: запрет, если цель = узел или лежит в его
поддереве; ёмкость цели проверяется до открепления (нет сирот);
детач-до-добавления (нет дублей в children).

## Средние / низкие

- **`#build-img-leak`** (proc.c): все пути ошибок `build_user_image`
  утекали уже выделенные фреймы сегментов, kmalloc-массивы и стек;
  переполнение argv (32×1022 байта) делало утечку юзер-триггеримой —
  МБ за неудачный execve. Фикс: общая метка `build_fail` с полной
  очисткой и перемоткой уже записанных PTE (чтобы destroy PML4 не
  делал double-free); pa-массивы реестра g_xv освобождаются при
  перезаписи (было: утечка на каждый exec).
- **`#brk-oom-leak`** (syscall.c): при OOM середины роста brk
  полуотображённые страницы оставались мапнутыми — следующий brk
  перекрывал их свежими фреймами, старые осиротевали. Фикс: откат.
- **`#wait4-echild`** (proc.c): процесс без детей крутился в
  task_yield() вечно (Linux: немедленный -ECHILD); WNOHANG возвращал 0.
- **`#mouse-midpacket-resync`** (mouse.c): ресинхронизация срабатывала
  на байтах данных X/Y с битом 3 (легитимно у половины значений) —
  быстрое движение разваливало поток пакетов (мусорные дельты,
  фантомные клики). Проверка правдоподобия — только для байта 0.
- **`#fs-sparse-leak`** (fs.c): дыра sparse-write не обнулялась —
  содержимое кучи ядра (данные ранее освобождённых объектов) читалось
  из ring 3. Фикс: kmemset дыры.
- **`#dns-label-overflow`** (tlsglue.c): длина DNS-метки проверялась
  ПОСЛЕ записи — переполнение q[512] на стеке ядра из консольной
  команды https. Фикс: ≤63 (RFC 1035) до записи + общая длина.
- **`#https-req-overread`** (tlsglue.c): kvsnprintf возвращает
  «желаемую» длину (C99) — при длинном path/host цикл читал req[512..l]
  (неинициализированный стек ядра) и отправлял на сервер. Фикс: clamp.
- **`#tcp-demux-no-ip`** (net.c): демультиплексирование TCP совпадало
  только по портам — два пира с одним source-port попадали в один
  сокет. Фикс: полное 4-tuple сравнение.
- **`#evdev-modifier-mirror`** (keyboard.c): Ctrl/Alt/Caps не
  зеркалились в evdev-поток (только Shift) — libinput/Wayland-клиенты
  не видели модификаторов. Фикс: зеркало make/break без пуша в
  консольное кольцо.
- **`#r2c-bounds-order`** (scheduler.c): диагностический printf
  разыменовывал `tasks[slot]` ДО bounds-проверки.
- **`#ping-octet`** (net.c): запись `target_ip[4]` при четвёртой точке
  (1 байт за массивом) + отсутствие клэмпа 255.
- **`#dnsrx-overread`** / **`#rxraw-overread`** (net.c, rtl8139.c):
  отладочные чтения за границей буферов (утечка в serial). Фикс: guards/wrap.
- **`#pmm-carve-unbounded`** (mm.c): на RAM > ~1.4 ГБ таблица
  refcount'ов выходила за 2 МБ carve-зоны, не резервируясь в битмапе —
  аллокатор раздавал те же фреймы под данные пользователя. Фикс: зона
  растёт с повторным резервированием.

## Осознанно НЕ исправлено (требует загрузочных тестов на QEMU)

Зафиксировано для следующей итерации (каждое — деликатное изменение
семантики путей контекста/сигналов, где регресс дороже бага):

1. **rt_sigreturn** восстанавливает RAX = номер прерванного syscall
   (130) вместо -EINTR для rt_sigsuspend — blob копируется до записи
   возврата syscall_entry.S. Нужна коррекция слота RAX в blob.
2. **FPU/SSE при fork/spawn**: ребёнок получает fninit-шаблон, а не
   живое состояние родителя; свежий образ наследует XMM-регистры
   предыдущей задачи (утечка регистров между процессами). Нужен
   fxrstor в точке первого входа.
3. **kill(self, SIGSTOP)** в однозадачном случае не останавливает
   (task_yield без наследника дышит hlt и возвращается).
4. **Сироты-зомби** убираются только внутри task_create — долгоживущая
   система накапливает слоты/стеки.
5. **SMP-окно**: AP делает `sti` до `lidt`; при любом IRQ в этом окне —
   #GP/triple fault. Плюс AP используют IDT BSP без per-CPU состояния.
6. **pmm_ref/pmm_unref без锁**: безопасно, только пока AP сидят в hlt.
7. **Сигнальная смерть** кодируется как обычный exit-код (WIFSIGNALED
   не различается), кроме уже корректного stop-report.
8. **Слоты задач**: `proc_alloc_slot` форс-рециклит непожатых зомби
   (wait4 родителя крутится вечно); рассмотреть отдельный reaper.

## НОВЫЕ ФИКСЫ

### #audit-mmap-regression (КАРДИНАЛЬНЫЙ, регресс аудита)
- **Симптом**: wltest t4 FAIL mmap; layertest exit=1; drmtest «FAIL mmap A»;
  в serial `[MMAP] addr=0 len=2000 ...` без продолжения.
- **Корень**: `vmm_range_is_user()` (фикс #uaccess-supervisor-hole) был
  подключён и к ЦЕЛЯМ мапинга в `sys_mmap_impl`. Каждый PML4 процесса
  наследует supervisor identity-alias [4MB,1GB); собственный mmap-регион
  ОС — [512MB,768MB), т.е. ВНУТРИ окна alias. Walker видел
  present-без-VMM_USER по адресу 0x20000000 ДО того, как `vmm_map()`
  перезаписал бы записи user-страницами → -ENOMEM на каждый fd-backed
  mmap (memfd/`/dev/shm`/DRM dumb).
- **Фикс**: `mmap_range_ok()` (syscall.c) — статические диапазонные
  правила без walker'а — для всех четырёх веток цели мапинга
  (memfd/DRM/MAP_FIXED anon/shm). Walker остаётся в силе для ВСЕГО
  буферного I/O (read/write/poll/ioctl-arg) — ядро не «читает» память
  через цель мапинга, оно её ЗАМЕНЯЕТ (как sys_brk всегда рос поверх
  alias без проверок).
- **Сопутствующий guard**: `vmm_leaf_is_user()` (mm.c/mm.h) — MAP_FIXED
  замещение освобождает старый фрейм ТОЛЬКО если старый leaf несёт
  VMM_USER. Alias-фреймы (живая RAM ядра!) никогда не отдаются в PMM —
  закрывает и до-аудиторскую дыру double-alloc (huge-PDE alias вообще
  не unmap'ится 4K-unmap'ом, а PA отдавался в PMM).

### #fs-size-symlink (ВЫСОКИЙ, до-аудиторский)
- **Симптом**: `elf /bin/sh /t.sh` → «[ELF] Failed to create process»
  (process_spawn вернул голый -1 без диагностики); `elf /bin/busybox`
  работал. serial упирался в `[SPAWN] enter path=/bin/sh`.
- **Корень**: `fs_file_size()` резолвил путь через NO-follow резолвер
  (`fs_resolve_path`), а `fs_open()` — через follow (`..._follow`).
  Любой путь, оканчивающийся симлинком (54 applet-линка: /bin/sh, /bin/wc,
  ...), давал FS_ERR_NOTFOUND при query размера, хотя тот же путь
  открывался.
- **Фикс**: fs_file_size использует follow-резолвер (size — stat-class
  операция). Единственный потребитель — process_spawn; симлинк-пути
  теперь exec'аются.
